# Database

The admin shares one Supabase project (`cre8-advisors`, ref `xrgfupoyaexgcrtxmqpp`)
with **cre8-map**. Only cre8-admin's 16 tables are tracked here; the map's tables
(`sale_comps`, `census_tracts`, `zoning_sources`, `site_plans`, `planning_events`, …)
and PostGIS belong to that repo.

## Files

- `migrations/2026-11-16_baseline_schema.sql` — a full capture of the 16 admin
  tables as deployed, generated by `scripts/capture-schema.js`. Everything in it
  is idempotent, so running it against the live project is a no-op.
- `migrations/2026-09-*.sql` — the incremental email migrations that predate the
  baseline. Kept for history; the baseline already includes their effect.

Before the baseline existed, 10 of the 16 tables had no `CREATE TABLE` anywhere in
the repo — the deal pipeline and commission history lived only in production, and
there was no way to stand up a staging copy.

## Running SQL

`psql` is not installed and there's no direct connection string configured. Use
the Management API (`SUPABASE_ACCESS_TOKEN` is exported from `~/.zshrc`):

```bash
curl -s -X POST \
  "https://api.supabase.com/v1/projects/xrgfupoyaexgcrtxmqpp/database/query" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d @body.json          # {"query": "..."} — use a file to avoid shell quoting
```

DDL returns `[]`. For multi-statement SQL, write the JSON body to a file first.

## Making a schema change

1. Write a dated migration: `migrations/YYYY-MM-DD_what_changed.sql`.
2. **Dry-run it first.** Wrap it in `begin; … rollback;` and POST it. Postgres
   runs DDL inside transactions, so every statement executes and nothing
   persists — this catches syntax and dependency errors without touching data.
3. Swap `rollback` back to `commit` and run it for real.
4. Re-capture the baseline so it stays the source of truth:
   ```bash
   node scripts/capture-schema.js -o supabase/migrations/$(date +%F)_baseline_schema.sql
   ```
   Then delete the previous baseline file.

## Re-capturing

```bash
node scripts/capture-schema.js                  # print to stdout
node scripts/capture-schema.js -o path/to.sql   # write to a file
```

If you add a table, add it to the `TABLES` array in that script — it won't be
captured otherwise. `grep -rho '\.from("[a-z_]*")' src | sort -u` lists every
table the code actually touches, which is the list to reconcile against.

## RLS

RLS is not enabled on these tables, and the baseline does not add it. The admin
reaches Supabase only through server-side API routes using the service-role key,
which bypasses RLS by design. That makes the API routes the only access control —
see `src/middleware.ts`.
